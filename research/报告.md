# AutoCAD 2025 兼容性研究报告

> 分支：`research/autocad-2025-compat`
> 实测环境：AutoCAD 2025（R25.0.58.0，简体中文）、.NET SDK 10.0.201、运行时 .NET 8.0.21
> 结论日期：2026-10

## 一句话结论

**插件源码无需修改即可编译为 net8 产物并在 AutoCAD 2025 上加载运行；但 PdfSharp 在 .NET 8 下必须补一行 `Encoding.RegisterProvider`，否则所有 PDF 保存都会静默失败。**

---

## 1. 关键事实（推翻既有假设）

`docs/DESIGN.md` M8 的原计划基于三个假设，实测**两个是错的**：

| DESIGN.md 原假设 | 实测结果 |
|---|---|
| 需要下载 **ObjectARX 2013/2025 SDK** 才能编 net8 产物 | ❌ **不需要**。直接引用 AutoCAD 安装目录的 `acmgd.dll` / `acdbmgd.dll` / `accoremgd.dll` 即可编译 |
| 需要 `#if ACAD_NET8` 条件编译别名层（约 10 处） | ❌ **不需要**。`src/BPPlot.cs` + `BpForm.cs` + `BpMenu.cs` 三个文件**零修改**编译通过（0 错误） |
| net8 产物无法在本机验证，需 2025+ 机器 | ⚠️ 本机就是 2025，**可以完整验证** |

### 1.1 2025 程序集的目标框架

```
acmgd.dll       → .NETCoreApp,Version=v8.0
acdbmgd.dll     → .NETCoreApp,Version=v8.0
accoremgd.dll   → .NETCoreApp,Version=v8.0
AcCui.dll       → .NETCoreApp,Version=v8.0
```

2021–2024 是 .NET Framework 4.x，2025 起切到 **.NET 8**。这是硬分界：.NET Framework 的 `csc.exe` 无法引用 2025 程序集（会报 `CS0012` 缺 `System.Runtime` / `CS0616` `CommandMethodAttribute` 非特性类）。

## 3. 运行时验证（本报告最重要部分）

### 3.1 accoreconsole 2025 的调用方式坑（必读）

**在 Git Bash 里直接调用 accoreconsole 2025 会永久挂起**（脚本完全不执行）。

- 症状：进程存活、日志停在 `命令:` 提示符、`_.quit _y` 无效、只能 `timeout` 强杀。
- 根因：Git Bash 的管道 / POSIX 重定向与 accoreconsole 的 `Redirect stdout` 机制冲突。
- **解法：必须经 `cmd.exe` 包装**：

```cmd
@echo off
set ACC=D:\Program Files\Autodesk\AutoCAD 2025\accoreconsole.exe
"%ACC%" /i "输入.dwg" /s "脚本.scr" > "日志.log" 2>&1
echo EXIT=%errorlevel%
```

验证方法：在 `.scr` 里写标记文件（`(setq f (open "marker.txt" "w"))`），确认脚本真的执行了。经 `cmd` 包装后 `EXIT=0` 且标记文件生成。

### 3.2 `/loadmodule` 不注册命令，必须用 `netload`

| 加载方式 | `IExtensionApplication.Initialize` | `CommandMethod` 注册 |
|---|---|---|
| `/loadmodule xxx.dll` | ✅ 执行 | ❌ **不注册**（敲命令报"未知命令"） |
| `.scr` 里 `(command "_.netload" "...")` | ✅ 执行 | ✅ 注册 |

这与 2023 控制台的已知行为一致（README 踩坑记录第 2 条），2025 未改变。
**所以无头自动化仍必须走「USERS2 触发 + 加载即出图」或 `netload` + 显式命令。**

### 3.3 net8 产物在 2025 上确实能加载

`.scr` 内容（**必须 CRLF 行尾**）：

```lisp
(setvar "secureload" 0)
(setvar "filedia" 0)
(command "_.netload" "D:/path/BPPlotNet8.dll")
(princ "\nLOADED_OK")
_.quit _y
```

输出 `LOADED_OK` → 程序集加载成功，`Initialize` 已执行。

## 4. 唯一代码级障碍：PdfSharp 的编码问题（已定位并给出修复）

### 4.1 症状

net8 产物加载成功，但 `BPSELFTEST` 输出失败，且 `%APPDATA%\BPPlot\` 目录根本没创建（说明在写日志前就抛了异常）。

### 4.2 根因（已用反射探针逐层定位）

```
Runtime: .NET 8.0.21
PdfSharp loaded: PdfSharp, Version=1.50.5147.0
PdfDocument instance created OK
AddPage OK: PdfPage
Save FAIL → System.NotSupportedException:
   No data is available for encoding 1252.
   For information on defining a custom encoding,
   see the documentation for the Encoding.RegisterProvider method.
```

**`.NET Core` / `.NET 5+` 默认不内置非 Unicode 代码页**（1252 / 936 / GBK 等），而 PdfSharp 1.50 内部依赖 `Encoding.GetEncoding(1252)`。所以：

- `PdfDocument` 构造 ✅、`AddPage` ✅
- **`Save()` ❌** → 只写出 39 字节的残废文件

这会让 `CropPdf` / `MergePdfs` / `BPSELFTEST` **全部静默失败**（`CropPdf` 内是 `catch { return false; }`，只留下 `*.crop.pdf` 中间文件）。

### 4.3 已验证的修复

在 `App.Initialize()` 最开头加一行：

```csharp
System.Text.Encoding.RegisterProvider(System.Text.CodePagesEncodingProvider.Instance);
```

- 实测：注册后 `encoding 1252 => windows-1252`，`Save OK`，PDF 从 39 字节变为 **640 字节有效文件**。
- `CodePagesEncodingProvider` 在 .NET 8 运行时中**已内置**（`Type.GetType("System.Text.CodePagesEncodingProvider, System.Text.Encoding.CodePages")` 能取到），无需额外 NuGet 包。
- **`.NET Framework` 产物不需要这行**（4.x 自带全部代码页）。

**建议实现（不动 .NET Framework 产物行为）**：

```csharp
public void Initialize()
{
    // .NET 8+ 默认不含 ANSI 代码页，PdfSharp 1.x 内部用 1252 会抛
    // NotSupportedException → 所有 PDF 保存静默失败。仅 net8 产物需要。
#if NET8_0_OR_GREATER
    try { System.Text.Encoding.RegisterProvider(System.Text.CodePagesEncodingProvider.Instance); }
    catch { }
#endif
    // ... 原有逻辑
}
```

这是 DESIGN.md M8 说的「`#if ACAD_NET8` 别名层」里**唯一真正需要的那一处**。

## 6. 建议的落地步骤

1. **立即**：在 `App.Initialize()` 加上 §4.3 的条件编译修复（仅影响 net8 产物，Framework 产物不变）。
2. **补 `build_net8.cmd`**：复用 `build.cmd` 的 `ACAD=` 变量思路，指向 2025 安装目录，`dotnet build` 出 `BPPlotNet8.dll`。
3. **改 `build.cmd`**：`ACAD` 路径不能写死 2023；建议加 `ACAD_VER` 参数或自动探测注册表 `HKLM\SOFTWARE\Autodesk\AutoCAD\*\*\AcadLocation`。
4. **发布包**：`deploy/PackageContents.xml` 的 `SeriesMin/Max` 需按产物分档——Framework 产物 2021–2024（`R24.0`–`R24.3`）、net8 产物 2025+（`R25.0`+）。两个 bundle，或一份 XML 多 `ComponentEntry`。
5. **回归**：在 2025 上跑 `test/fixtest.scr` 等既有矩阵，用黄金页尺寸比对（见 AGENTS.md §5.5）。
6. **更新文档**：README 兼容性声明、`docs/DESIGN.md` M8（把"需下载 ObjectARX SDK"和"约 10 处条件编译"改成实测结论）。
