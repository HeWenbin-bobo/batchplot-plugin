## 1. 关键修复（否则整个 PDF 功能不可用）

### 1.1 问题链（三层，逐层暴露）

| 层 | 症状 | 根因 | 修复 |
|---|---|---|---|
| 1 | `BPSELFTEST` 失败，`%APPDATA%\BPPlot\` 未创建 | .NET 8 无内置 ANSI 代码页，PdfSharp 1.50 `Encoding.GetEncoding(1252)` 抛 `NotSupportedException` | `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` |
| 2 | 修复 1 后自检通过，但**实际出图裁切仍失败** | PdfSharp **1.50 无法解析 AutoCAD 2025 打印引擎产出的 PDF**：`PdfReaderException: Invalid entry in XRef table` | 升级 **PdfSharp 6.x** |
| 3 | 升级 6.x 后编译通过，但运行即崩 | PdfSharp 6.x 依赖 `Microsoft.Extensions.Logging.Abstractions` 等 **8 个包**，未随产物复制 | `<CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>` |

**三者缺一不可。** 第 2、3 层的失败都被 `CropPdf` 的 `catch { return false; }` 吞掉，用户侧只看到"裁切没生效"或"合并失败"，没有任何异常信息。

### 1.2 源码改动

`src/BPPlot.cs` 的 `App.Initialize()` 开头（仅 net8 产物生效）：

```csharp
#if NET8_0_OR_GREATER
    try { System.Text.Encoding.RegisterProvider(System.Text.CodePagesEncodingProvider.Instance); }
    catch { }
#endif
```

**这是为了让 PdfSharp 6.x 内部编码正常工作**（6.x 仍需要 codepage provider 处理中文字体/元数据）。.NET Framework 产物走 `#if` 排除，行为不变。

## 3. 发现的缺陷

### 3.1 【已修复】`BPL` 布局批量出图（原 `eLayoutNotCurrent` + 进程崩溃）

**原始症状**：
```
[FAIL] 1: eLayoutNotCurrent
[FAIL] 2: eLayoutNotCurrent
（随后进程崩溃）
```

**根因（两个独立缺陷叠加）**：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 遍历布局字典时**从不切换** `LayoutManager.Current.CurrentLayout` | `PlotInfo.Validate()` 抛 `eLayoutNotCurrent`（API 要求目标布局必须是当前布局） |
| 2 | `finally` 里无条件 `pe.EndPlot()` | 若所有布局都失败（零 `BeginDocument`），`EndPlot` 触发 **AccessViolation 0xC0000005**，不可捕获，直接杀进程 |

**修复**（`src/BPPlot.cs` `BpLayouts()`）：
```csharp
// 1) 先收集布局名，避免遍历字典时改动布局上下文
List<string> layoutNames = ...;   // 从 LayoutDictionary 收集，跳过 Model

foreach (string layName in layoutNames)
{
    LayoutManager.Current.CurrentLayout = layName;   // 关键：出图前切到目标布局
    ... BeginDocument / EmitPage / EndDocument ...
}

finally
{
    if (pe != null) {
        if (plotStarted) { try { pe.EndPlot(null); } catch { } }   // 零文档不 EndPlot
        ReleaseEngine(pe);
    }
    LayoutManager.Current.CurrentLayout = prevLayout;   // 无论成败都恢复用户原布局
}
```

**验证**（accoreconsole + 自建 2 布局测试图，含 2 个已配置纸张的图纸空间布局）：
```
  [OK] 布局1 -> 布局1.pdf
  [OK] 布局2 -> 布局2.pdf
BPL_SUMMARY OK=2 FAIL=0
```
PDF `/MediaBox` 实测：两份均 `297.0 × 420.2 mm`（A3，与配置一致）。

---

### 3.1b 【已修复】出图引擎不释放 → 同一会话第二次出图静默失败

**症状**：脚本/工作流里连续两次出图，第二次报 `BPLOT 致命错误: ePlotAlreadyStarted`，且 `OK=0 FAIL=0`（用户只看到"第二次没出图"）。

**根因**：`EndPlot()` 只结束这一轮出图事务，**不回收 COM 端引擎实例**。`PlotEngine` 实现了 `IDisposable`，还有显式 `Destroy()`；两者都没调用。

**修复**：新增 `ReleaseEngine(pe)`（`Destroy()` + `Dispose()`，各自 try/catch），在 `PlotFrames2` / `BpLayouts` / `BPPREVIEW` 的所有退出路径调用。

**验证**（同一 `.scr` 连跑 3 次，同一会话连跑 3 次 `BPLOTAUTO`）：
```
第1次: BPLOT_SUMMARY OK=3 FAIL=0
第2次: BPLOT_SUMMARY OK=3 FAIL=0   ← 修复前此处是 ePlotAlreadyStarted
第3次: BPLOT_SUMMARY OK=3 FAIL=0
```
另测 `BP1 → BP1 → BPLOTMERGE` 连跑：三次全部 `OK=3 FAIL=0`。

---

### 3.1c 【已修复】`DropContained` 排序不稳定 → Sheet 编号跨次抖动

`List.Sort` 是不稳定排序。A1 横/竖两个图框面积完全相同（4.99M 单位²），两次运行顺序互换，导致 `Sheet001/Sheet002` 对应的图框漂移。

**修复**：`DropContained` 加二级/三级/四级排序键（面积降序 → MinX → MinY → 宽度），结果确定。

**验证**：连续 3 次回归，`Sheet001/002/003` 尺寸集合逐字节一致。

---

### 3.1d 【已修复】`BpForm` 表格列可排序 → 行内改的文件名静默落到别的图框

**症状**：用户在对话框里点"图号"列标题排序后，在第 1 行改文件名/比例，出图时这些修改落到了**别的图框**上，无任何提示（错图）。

**根因**：`ApplyAndClose()` 用 `r.Index`（行位置）取 `_frames[r.Index]`，是**位置绑定**。`DataGridViewTextBoxColumn.SortMode` 默认值是 `Automatic`（实测确认），点表头即排序，行序与 `_frames` 索引脱钩。

**实证**（`test/gui/BpFormTest`，无头实例化 `BpForm`）：
```
修复前: 排序后首行显示=A-102  写回落到=A-101/FIRST_ROW_NAME   ← 错位
修复后: 可排序列数=0
        排序后首行显示=A-101  写回落到=A-101/FIRST_ROW_NAME   ← 一致
```

**修复**（`src/BpForm.cs`）：`AddRange` 后逐列 `SortMode = DataGridViewColumnSortMode.NotSortable`。

---

### 3.2 【设计行为，非缺陷】`BP1` 处理了 3 个图框

`BP1` 名为"单张快打"，但 `CollectFrames` 会收集选择集里**全部**图框。测试中 `_all` 选中 3 个 → 输出 3 页。这是"不弹对话框、用默认参数"的语义，不是"只打一个"。若用户期望"只打一个"，应在选择时只选一个实体。

### 3.3 【测试陷阱】`USERS2` 预设会误触发"加载即出图"

首次测试 `BPSPLIT` 时，脚本先设了 `USERS2` 再 `netload`，导致 `Initialize` 判定为 accoreconsole 场景并直接跑 `BPLOTAUTO`，随后进程崩溃。

**正确写法**：先 `netload`（`USERS2` 为空），再设 `USERS2`，再执行目标命令。

```lisp
(setvar "users2" "")
(command "_.netload" "D:/path/BPPlot.dll")
(setvar "users2" "D:/output")     ; 此时才设
BPSPLIT
```

### 4.4 `BPLOT` 交互对话框 — 受限于模态对话框

**仍未能脚本化驱动**，原因已定位并记录：
- `SendCommand("BPLOT
ALL
")` 进入 `ShowModalDialog` 后，AutoCAD 主线程被模态循环占用，后续任何 COM 调用一律返回 `RPC_E_CALL_REJECTED (0x80010001)`；
- 后台进程发送的 `SendCommand` 同样被阻塞，实测在对话框打开期间后台 PowerShell 无法退出（`BG exited=False`）；
- 窗口枚举只看到 `AfxMDIFrame140u` 与两个无标题 `HwndWrapper`，**没有**独立顶层对话框窗口（`ShowModalDialog` 用的是 AutoCAD 自己的模态窗口容器）；`PrintWindow` 抓到的画面为空。

**替代覆盖**：对话框的全部业务逻辑已由 §4.1 的 24 项无头单测覆盖（它自己就是一个独立 WinForms 窗体，脱离 AutoCAD 即可实例化）。**只有"从 AutoCAD 命令走到 `ShowModalDialog` 这一跳"未验证**，但该跳在 `BPLOT` 命令体内，代码路径与 `BPPREVIEW`/`BPL` 一致（都调 `CollectFrames` + `BuildPage`），且 `BPLOTAUTO` 已端到端验证。

### 4.5 `BPTEACH` 图框学习 — 半验证

`GetEntity` 交互拾取在 accoreconsole 下无法脚本化喂点（实测重试 5 种输入格式：`2000,28000` / `21000,0` / `7000,7000` / 隐式选择集 / `ALL`，均返回"未选中对象"）。GUI 侧同样被 `RPC_E_CALL_REJECTED` 卡住。

**替代覆盖**：用 `test/gui/MkBlockDwg` 生成 `test/fixtures/blk.dwg`（图块 `TITLEBLOCK_A3` + 属性 `TUHAO/TUMING/BILI/BANCI/RIQI`），再手工写入与 `BPTEACH` 相同格式的配置（`%APPDATA%\BPPlot\config.json`），验证"学习结果能被识别链路消费"：
```json
{ "frameBlocks": ["TITLEBLOCK_A3"], "numberTags": ["TUHAO"], "nameTags": ["TUMING"],
  "scaleTags": ["BILI"], "revTags": ["BANCI"], "dateTags": ["RIQI"] }
```
块名 `TITLEBLOCK_A3` 与属性标签 `TUHAO/TUMING/BILI` 均**不匹配**任何内置猜测规则，只可能来自配置：
```
BPLOT v0.7: 2 个图框，比例 1:100
  [OK] 建-101_建筑设计说明.pdf
  [OK] 建-102_首层平面图.pdf
BPLOT_SUMMARY OK=2 FAIL=0
```
文件名由 `{图号}_{图名}` 模板 + 学习标签正确拼出 → **学习结果 → 自动识别 → 输出命名** 全链路成立。未验证的只剩"拾取动作本身"。

|---|---|---|---|
| 1 | `BPL` 不切当前布局 → `eLayoutNotCurrent` | 功能完全不可用 | ✅ 已修复并验证 |
